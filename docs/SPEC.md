## 0. 1차 목표: 1강 "한 자리 곱셈" — 문제 풀기 중심(2026-11-09)

**문제를 풀고 맞히는 것이 중심이다. 강의는 잘 모르겠을 때 찾아서 본다.**

### 0.1 화면
- **지도:** 블록 섬(강)들. 1강 "한 자리 곱셈" 섬만 열려 있고, 나머지는 "준비 중". 섬마다 "문제 풀기"와 "강의 보기".
  - 그 아래: 기술 배지 선반, 선생님 꾸미기(배지로 연 것을 입히고 벗기기), 나의 기록(끝까지 푼 판, 가장 빠른 기록).
- **풀기:** 위에 진도 줄(8칸 + 보너스 칸, ★ 한 번에 맞힘 / ○ 다시 해서 맞힘 / △ 같이 풀었음), 블록 세상 무대의 큐브 선생님, 대화창(이름표, 한 글자씩 나타나는 자막), 칠판, 실물과 똑같은 17줄 주판, 한 줄 숫자판.
- **강의 보기:** 지도에서, 또는 문제를 풀다가 누른다. 강의(복습 → 두 자리 소개 → 같이 풀기 2 → 세 자리 소개·0 붙이기 → 같이 풀기 2)를 본 뒤 그 문제로 돌아온다. 강의 보는 시간은 기록에 넣지 않는다.

### 0.2 한 판(`src/core/practice.js`)
1. 여덟 문제를 쉬운 것부터 낸다: 두 자리(받아올림 없음 → 있음 → 0 붙이기) → 세 자리(0 붙이기 → 곱이 0 → 0 붙이기와 받아올림 함께).
2. 아이는 실물 주판으로 풀고 말로(또는 숫자판으로) 답한다.
3. 한 번에 맞히면 주판이 반짝이고 "띵동" 소리와 함께 칭찬한다.
4. 처음 틀리면 무엇을 놓쳤는지 짐작해 짚어 주고 한 번 더 풀게 한다. 두 번 틀리면 선생님이 화면 주판으로 같이 놓아 보인다. "같이 풀어 줘요"를 누르면 바로 같이 놓는다.
5. 여덟 문제를 마치면 보너스 문제를 풀지 아이가 고른다(네 / 아니요).
6. 끝: 맞힌 수, 나와의 기록(지난번 가장 빠른 기록과만 비교), 새 배지와 꾸미기, 인사, 쓰러지며 끝 소리. "한 판 더"는 아이가 누를 때만.

## 2. 절대 원칙 (모든 단계에서 지킨다)

### 2.1 중독 방지

> **2026-11-09 바뀜:** 학습 앱이라 실력과 묶인 게임 요소(강 지도, 기술 배지, 배지로 여는 선생님 꾸미기, 나와의 기록, 고르는 보너스 문제, 처음 해낸 순간의 축하, 순간 반짝임)는 넣는다. 아래 표에서 "배지"와 "요란한 칭찬"은 이 범위 안에서 허용한다. 무작위 보상, 연속 출석, 카운트다운, 순위표, 하트(목숨)는 계속 넣지 않는다. 화면은 블록 게임 느낌으로 꾸미되 특정 게임의 그림·글꼴·로고·효과음은 쓰지 않는다.

| 넣지 않는 것 | 대신 이렇게 |
|---|---|
| 점수, 별, 배지, 등급, 순위표, 급수 표시 | 기술 지도에 "됨 / 거의 / 아직"만 보여준다(6장) |
| 제한 시간, 카운트다운, 빨리 하라는 재촉 | 선생님은 아이가 버튼을 누를 때까지 기다린다. 걸린 시간은 기록에 사실로만 남긴다 |
| 연속 접속 보상, 출석 체크, 안 하면 줄어드는 수치 | 기술 지도는 쉬어도 그대로 기다린다. 선생님도 "오랜만이에요" 같은 말로 탓하지 않는다 |
| 알림, 푸시, 빨간 숫자 배지 | 없음 |
| 자동으로 이어지는 다음 수업 | 한 수업(기본 10문제)이 끝나면 선생님이 정리하고 멈춘다 |
| 요란한 칭찬, 효과음 폭죽, 틀릴 때 벌 | 선생님은 무엇을 잘했는지 구체적으로 말한다. 틀리면 어디서 틀렸는지 함께 본다 |
| 광고, 외부 링크, 결제, 사용 추적 | 없음. 단, 말로 대답하기(7.2절)에 쓰는 브라우저 음성 인식은 허용한다 |

**숫자 부르는 빠르기:** 듣고 풀기(호산)와 플래시 암산의 빠르기는 아이가 고르는 **설정**이다. 카운트다운이 아니다. 앱이 저절로 빠르기를 올리지 않는다.

### 2.2 정직함

- **기술 지도는 짐작이다.** 최근 몇 문제로 정한다는 것을 화면에 적는다("최근 8문제 중 7문제를 맞혔어요").
- **오답 진단도 짐작이다.** 선생님은 "~한 것 같아요"라고 말한다.
- **같은 수업 번호는 언제나 같은 문제다.** 문제 만들기는 시드로 정해진다. 그래서 "어제 그 문제 다시 풀기"가 된다.
- **급수로 바꿔 말하지 않는다.** 단체별 기준이 궁금하면 부모가 `docs/research-curriculum.md`를 본다.

### 2.3 아이 눈높이

- 한 화면에 한 가지 일만 한다.
- "~해요"체, 한 문장에 한 가지 뜻. 선생님 대사도 같다.
- 선생님이 하는 말은 **늘 자막으로도** 보여준다. 소리를 끄거나 목소리가 안 나는 기기에서도 수업이 된다.
- 주판 용어는 쉬운 말과 함께 쓴다.

| 쓰는 말 | 함께 보여주는 풀이 |
|---|---|
| 친구수 | 더해서 10이 되는 수(예: 7의 친구수는 3). 아이가 보는 강의에서 쓰는 말이다 |
| 5의 짝 | 더해서 5가 되는 짝(1과 4, 2와 3) |
| 윗알 / 아래알 | 5짜리 알 / 1짜리 알 |
| 자리 / 줄 | 몇 자리 수 / 몇 개를 더하고 빼나 |

"보수"는 학원에서 쓰는 말이라 낱말 카드로 연결한다.

## 3. 사용자 가정

- **아이**
  - 초등 3~4학년, 학원에서 주산을 배우는 중이다.

- **조작**
  - 실물 주판을 쓰느라 손이 바쁘다. 그래서 화면 조작은 **큰 버튼 몇 개와 숫자판**으로 줄인다.

## 4. 주판 모델 (순수 함수)

### 4.1 주판 상태

- 주판은 자리(줄)의 배열이다. 오른쪽 끝이 일의 자리다. 기본은 9자리다.
- 각 자리는 윗알 `u`(0 또는 1)와 아래알 `l`(0~4)이고, 값은 `5u + l`이다.
- **변환 함수:** 숫자를 주판 상태로, 주판 상태를 숫자로 바꾸는 함수를 둔다. 둘은 서로 되돌릴 수 있어야 한다.

### 4.2 기법 판별

한 자리에 수 `d`(1~9)를 더하거나 뺄 때 쓰는 기법을 아래처럼 정한다. 이 판별이 앱의 심장이다.
- 높은 자리부터 놓는다.
- 받아올림과 받아내림은 바로 윗자리에서 처리한다.

**덧셈** (지금 자리 값 `v = 5u + l`)

| 조건 | 기법 | 예 |
|---|---|---|
| `v+d ≤ 9`, 아래알만 움직임 | **A1 바로 넣기(1짜리 알)** | 1+3 |
| `v+d ≤ 9`, 윗알을 내림 | **A2 바로 넣기(5짜리 알 함께)** | 2+6, 0+5 |
| `v+d ≤ 9`, `d ≤ 4`, 아래알이 모자람 | **A3 5의 짝 덧셈**: 윗알 내리고 (5−d) 빼기 | 3+4 |
| `v+d ≥ 10`, 이 자리에서 (10−d)를 바로 뺄 수 있음 | **A4 친구수 덧셈**: (10−d) 빼고 윗자리에 1 | 7+5, 4+8 |
| `v+d ≥ 10`, (10−d)를 빼려면 5의 짝이 필요함 | **A5 친구수와 5의 짝 함께** | 5+6, 6+7 |
| 윗자리에 1을 더하다 또 받아올림이 생김 | **A6 이어서 받아올리기** | 95+7 |

**뺄셈**은 덧셈을 거울처럼 뒤집어 B1~B6을 정한다.
- B1 바로 빼기(1짜리 알), B2 바로 빼기(5짜리 알 함께)
- B3 5의 짝 뺄셈: 아래알 (5−d) 넣고 윗알 올리기. 예: 7−3
- B4 친구수 뺄셈: 윗자리에서 1 빼고 이 자리에 (10−d). 예: 12−5
- B5 친구수와 5의 짝 함께. 예: 13−7
- B6 이어서 받아내리기. 예: 102−5

**판별 결과:** 한 문제의 판별 결과는 단계 목록이다. 단계마다 몇째 줄, 몇째 자리, 어떤 기법을 썼는지 적는다.
- 여기서 **기법 집합**(그 문제에 나온 기법들)이 나온다.
- 선생님 설명(7.3절)과 화면 주판 시연도 이 단계 목록을 그대로 쓴다.

### 4.3 곱셈·나눗셈 (나중 단계)

**곱셈(한 자리 × 여러 자리)** — 아이가 보는 강의에서 확인한 방법(부모가 받아 적은 메모, `assets/lesson-notes/`)

1. **자릿수:** 두 수의 자릿수를 더한 만큼이 답의 자리 수다. 그 자리에서 놓기 시작한다(3자리면 백, 4자리면 천).
2. **순서:** 여러 자리 수의 앞자리(높은 자리)부터 한 자리 수와 곱한다.
3. **곱은 늘 두 칸:** 곱이 한 자리면(0 포함) 앞에 0을 붙인다. 예: 4 × 2 → "08", 6 × 0 → "00". 강의가 "제일 중요하다"고 두 번 짚은 점이다.
4. **더하기:** 다음 곱은 한 칸 오른쪽에서 시작해 주판에 더한다. 더할 때 덧셈 기법(바로 넣기, 친구수 등)을 쓴다. 그래서 4.2절 판별기로 곱셈 문제의 더하기 단계도 판별한다.
5. **답 쓰기:** 천의 자리(자리점)에 콤마를 찍는다. 답이 자릿수 규칙보다 짧을 수 있다(맨 앞이 0, 예: 33 × 2 = 66).

예: 9 × 58 → 백부터 45 → 72를 한 칸 오른쪽에 더함(십의 자리에서 친구수: 1 올리고 3 빼기) → 522.

곱셈 기법 칸(기술 지도): 구구, 시작 자리 찾기, 0 붙이기, 더할 때 받아올림 없음 / 있음.
선생님 말: "사 곱하기 이는 팔. 한 자리니까 앞에 영을 붙여요. 영팔." "삼십, 백의 자리에서 끝났어요."

## 5. 문제 만들기 (순수 함수, 결정론)

- **입력:** 시드, 목표 기법, 허용 기법 집합, 크기(자릿수 범위, 줄 수, 빼기 줄 수)
- **출력:** 문제 하나(수의 목록, 정답, 판별 결과)
- **방법:**
  1. 시드 난수(`src/core/rng.js`)로 후보를 만든다.
  2. 판별해서 "목표 기법이 한 번 이상 들어 있고, 허용하지 않은 기법은 없다"를 만족하면 쓴다.
  3. 정해진 횟수 안에 못 찾으면 손으로 만든 예비 문제(`src/content/fallback.json`)에서 고른다.
- **빼기 줄 수 기본값:** 3~4줄 문제는 1줄, 5~7줄은 2줄, 8~10줄은 3줄이다. 한 단체 규정을 참고했다(research 3절).
- **중간 합:** 중간 합은 0보다 작아지지 않게 한다. 음수 답은 나중에 따로 켠다.
- **같은 수업 다시 풀기:** 수업 번호와 문제 번호로 시드를 정한다.

## 6. 기술 지도와 실시간 레벨 체크

### 6.1 무엇을 재나

실력을 두 축으로 나눠 잰다. 축을 곱해서 칸을 만들지 않는다. 칸이 너무 많아지지 않게 하려는 것이다.

**기법 축** (작은 수에서 잰다)
- **기본 순서는 친구수 먼저다:** A1 → B1 → A2 → B2 → A4 → B4 → A3 → B3 → A5 → B5 → A6 → B6
- 부모 화면에서 "5의 짝 먼저"(A3·B3을 A4·B4보다 앞)로 바꿀 수 있다.

**크기 축** (이미 되는 기법만 써서 잰다) — 초안, 아이 반응을 보고 고친다

| 칸 | 크기 | 칸 | 크기 |
|---|---|---|---|
| S1 | 1자리 3줄 | S8 | 2자리 7줄 |
| S2 | 1자리 4줄 | S9 | 3자리 5줄 |
| S3 | 1자리 5줄 | S10 | 2~3자리 7줄 |
| S4 | 1~2자리 5줄 | S11 | 3~4자리 7줄 |
| S5 | 2자리 3줄 | S12 | 3~5자리 8줄 |
| S6 | 2자리 5줄 | S13 | 4~7자리 8줄 |
| S7 | 2~3자리 5줄 | S14 | 5~8자리 10줄 |

**방식:** 크기 축은 방식마다 따로 잰다.

| 방식 | 아이가 하는 일 |
|---|---|
| 주판 · 보고 풀기 | 화면 문제를 보고 실물 주판으로 계산 |
| 주판 · 듣고 풀기 | 선생님이 불러 주는 수를 실물 주판에 놓기(호산) |
| 암산 · 듣고 풀기 | 선생님이 불러 주는 수를 머리로 계산 |
| 암산 · 플래시 | 숫자가 한 줄씩 나타났다 사라짐 |

암산은 주판보다 작은 크기에서 시작한다.

### 6.2 칸의 상태 (됨 / 거의 / 아직)

칸마다 **최근 8번**의 결과(맞음·틀림, 걸린 시간)를 둔다.

| 상태 | 조건 (초안 값, `src/content/mastery.json`에서 조정) |
|---|---|
| 아직 | 기록이 3번보다 적거나, 정답률이 50%보다 낮다 |
| 거의 | 아직도 됨도 아니다 |
| 됨 | 6번 이상 풀었고, 최근 8번 중 7번 이상 맞혔다 |

- **걸린 시간은 상태를 정하는 데 쓰지 않는다.** 기록 화면에 "한 문제 평균 12초 → 9초"처럼 사실로만 보여준다.
- 상태는 문제를 풀 때마다 바로 다시 계산한다. 이것이 **실시간 레벨 체크**다.

### 6.3 결과를 어느 칸에 넣나

- **맞으면:** 그 문제의 기법 집합에 든 모든 기법 칸과, 그 크기 칸에 "맞음"을 넣는다.
- **틀리면:** 실물 주판은 알 움직임을 알 수 없다. 그래서 오답과 정답의 차이로 짐작한다.

| 차이 | 짐작 | 선생님 말 (예) |
|---|---|---|
| ±10, ±100 … (10의 거듭제곱) | 그 자리의 친구수(받아올림·받아내림)를 놓쳤다 | "십의 자리에 1 올리는 걸 놓친 것 같아요" |
| ±5, ±50 … | 그 자리의 5의 짝을 놓쳤다 | "일의 자리 윗알을 한번 볼까요?" |
| 그 밖 | 알 수 없다. 크기 칸에만 "틀림"을 넣는다 | "같이 한 줄씩 다시 놓아 봐요" |

- 짐작 진단은 순수 함수(`src/core/diagnose.js`)로 두고 테스트를 붙인다.

### 6.4 다음 문제 고르기 (결정론)

한 수업 안에서 문제 번호에 따라 목적을 돌아가며 정한다.
- 10문제마다: 연습 7, 복습 2, 도전 1 (`src/content/mastery.json`)
  - **연습:** 순서상 가장 앞에 있는 "거의" 칸. 없으면 첫 "아직" 칸
  - **복습:** "됨" 칸 가운데 하나(시드로 고른다)
  - **도전:** 연습 칸 바로 다음 칸
- **기법을 연습할 때:** 크기는 "됨"인 가장 큰 크기보다 작게 둔다. 한 번에 한 가지만 어렵게 한다.
- **크기를 연습할 때:** "됨"인 기법만 섞는다.

### 6.5 화면에 보여주기

- **기술 지도:** 칸마다 이름과 상태를 보여준다.
  - 상태는 아이콘 개수(●○○ / ●●○ / ●●●)와 글자로 나타낸다. 색만으로 뜻을 전하지 않는다.

## 7. 화면 속 선생님 (기본 인터페이스)

### 7.1 무엇을 하나

선생님은 수업의 진행자다. 모든 모드(8장)는 선생님이 말로 이끈다.

| 하는 일 | 예 |
|---|---|
| 인사와 오늘 할 것 | "오늘은 친구수 덧셈을 해 볼 거예요. 주판을 준비해요." |
| 설명 | "7에 5를 더할 때, 일의 자리에는 5가 없어요. 그래서 친구수를 써요." |
| 시연 | 화면 주판에서 알을 한 단계씩 움직이며 말한다 |
| 숫자 불러 주기(호산) | "삼십이 … 더하기 십오 … 빼기 칠 … 은?" |
| 기다리기 | 아이가 "다 했어요"를 누를 때까지 조용히 기다린다 |
| 답 확인 | "맞았어요. 친구수를 정확히 썼어요." / "답이 10 작아요. 받아올림을 놓친 것 같아요." |
| 다시 해 보기 | 틀린 문제를 한 줄씩 다시 불러 주며 함께 놓는다 |
| 정리 | "오늘 10문제 중 8문제를 맞혔어요. 친구수 덧셈이 '거의'에서 '됨'이 됐어요. 오늘은 여기까지예요." |

### 7.2 아이가 하는 일 (화면 조작)

실물 주판을 쓰느라 손이 바쁘다. 그래서 **말로 대답하는 것이 기본이다.** 선생님처럼 아이도 말로 주고받는다.

**말로 대답하기**
- 선생님이 "은?" 하고 물으면 듣기를 시작한다. 아이가 "삼백이십오" 또는 "325"라고 말하면 답으로 받는다.
- 선생님이 말하는 동안에는 듣지 않는다. 선생님 목소리를 아이 대답으로 잘못 듣지 않게 하려는 것이다.
- 듣는 중에는 화면에 마이크 표시와 알아들은 글자를 보여준다.
- 알아들은 수가 애매하면 선생님이 되묻는다("삼백이십오라고 했어요?" → "네" / "아니요").
- 아래 말들도 알아듣는다. 낱말 목록은 `teacher.json`에 둔다.

| 아이 말 (예) | 뜻 |
|---|---|
| "다 했어요", "다 놨어요" | 주판에 다 놓았다 |
| "다시요", "다시 말해 주세요" | 방금 한 말이나 불러 준 수를 다시 듣는다 |
| "천천히요" | 이번 수업의 부르는 빠르기를 한 단계 늦춘다 |
| "그만할래요" | 수업을 끝낸다. 선생님은 지금까지 한 것을 정리하고 멈춘다 |
| "네", "아니요" | 되묻는 말에 대답한다 |

**화면 버튼** (말이 안 될 때, 늘 함께 둔다)
- 위 다섯 가지와 같은 버튼, 그리고 숫자판(0~9, 지우기, 확인)이다.
- 음성 인식이 안 되는 브라우저이거나, 인터넷이 끊겨 인식이 멈추거나, 부모가 꺼 두면 버튼과 숫자판으로 수업한다.

### 7.3 대사는 어떻게 만드나 (순수 함수)

- **대사 정하기**
  - 선생님이 할 말은 `src/core/teacher.js`의 순수 함수가 정한다.
  - 입력은 수업 상태(기술 지도, 지금 문제, 판별 결과, 진단)이고, 출력은 말 조각의 목록이다.
  - 말 조각마다 글자, 쉼, 화면 동작(시연할 알 움직임 등)을 담는다.
- **대사 원본:** 대사 틀은 `src/content/teacher.json`에 둔다. 부모나 아이가 고치고 싶은 말은 여기서 고친다.
- **같은 상황에서 고르는 말:** 같은 상황에 쓸 말이 여러 개면 시드로 고른다. 그래서 같은 수업은 같은 말을 한다.
- **숫자 읽기:** 숫자를 한국어로 읽는 함수(325 → "삼백이십오")를 따로 두고 테스트한다.
  - 학원이나 강의에서 숫자를 부르는 말투(예: 끝에 붙이는 말)는 아이에게 확인한 뒤 정한다(14장).
- **숫자 알아듣기:** 거꾸로, 인식된 글자를 숫자로 바꾸는 함수도 둔다(`src/core/numhear.js`).
  - "삼백이십오", "325", "삼백 이십 오", "삼백스물다섯"처럼 다르게 나와도 모두 325로 바꿔야 한다.
  - 인식기가 주는 후보 여러 개 중에서 숫자로 바뀌는 첫 후보를 쓴다.
  - 아무것도 숫자로 안 바뀌면 "다시 한 번 말해 줄래요?"라고 한다.
- **칭찬:** 구체적으로, 짧게, 차분하게 한다. 무엇을 잘했는지(기법 이름)를 말한다. "최고!", "천재!" 같은 말은 쓰지 않는다.
- **대사는 정해진 목록이다.** 목소리 파일을 미리 만들어야 하기 때문이다(7.6절).
  - `teacher.json`의 대사는 줄마다 `id`가 있다. 줄 안에 바뀌는 값(숫자, 이름)을 넣지 않는다.
  - 바뀌는 숫자는 숫자 조각 음성을 이어 말한다. 예: "오늘 맞힌 문제는" → "팔" → "문제예요"
  - `teacher.js`의 출력은 장면 목록이다. 장면마다 대사 `id` 또는 숫자 조각 목록, 자막 글자, 선생님 동작, 화면 동작을 담는다.

### 7.4 목소리

- **목소리는 하나로 일정한 어린이 목소리다.**
  - 지금은 기기 음성을 높게(높낮이 1.6), 조금 빠르게(1.05) 해서 어린이 목소리처럼 들리게 한다(`teacher.json`의 `voice`).
  - 진짜 어린이 목소리는 AI 음성 파일로 바꿀 때 어린이 목소리가 있는 서비스에서 고른다.
  - (한때 1~5글자마다 목소리를 바꿨으나 부모 요청으로 없앴다.)
- **AI 음성으로 미리 만든 파일을 쓴다.** 목소리 하나를 정해 모든 대사와 숫자 조각을 같은 목소리로 만든다(7.6절).
- **숫자 조각:**
  - 0~999 읽기, "천"이 붙은 1천~9천, "만"과 "억", "더하기", "빼기", "은?" 같은 말을 각각 파일로 만든다.
  - 숫자는 조각을 이어 읽는다. 예: 32,325 → "삼만" + "이천" + "삼백이십오"
  - 같은 조각을 **이어지는 말투**와 **끝나는 말투**(문장 끝, 묻는 끝) 두 가지로 만든다. 그래야 끊기는 느낌이 덜하다.
- **기기 음성은 대신 쓰는 것이다.**
  - 음성 파일이 아직 없는 대사(개발 중)에는 기기 음성 합성(`speechSynthesis`)을 쓴다.
  - 이때 지하철 게임의 `src/ui/ride-sound.js`에서 목소리 고르기, 안드로이드 Chrome 버그 피하기 부분을 가져온다.
- **듣기:** 브라우저 음성 인식(Web Speech API `SpeechRecognition`, Chrome은 `webkitSpeechRecognition`)을 한국어(`ko-KR`)로 쓴다.
  - 한 번 묻고 한 번 듣는 방식이다. 계속 켜 두지 않는다.
  - 처음 쓸 때 마이크 허락을 받는다. 허락하지 않으면 버튼으로 수업한다.
- **점검:** 처음 쓸 때 "말해 보기"로 마이크를 점검한다. 소리가 안 나면 자막만으로 수업한다.
- **빠르기:**
  - 대사는 만든 빠르기 그대로 쓴다.
  - 숫자 부르는 빠르기는 조각 사이의 쉼으로 조절한다. 아이가 고른다(2.1절).

### 7.5 모습 — 큐브 선생님 (아이가 설계함)

선생님은 정육면체 블록으로 만든 캐릭터다. 블록 게임 캐릭터 같은 모양이다. 크기는 아이가 정했다(한 칸 = 블록 한 개).

| 부분 | 크기(가로×세로×깊이) | 자리 |
|---|---|---|
| 몸통 | 19×19×6 (두께는 처음 19에서 얇게 고침) | 가운데 |
| 얼굴(머리) | 10×20×10 (세로는 처음 10칸의 2배) | 몸통 위 가운데. 눈과 입은 머리 가운데쯤 |
| 팔 2개 | 7.5×19×3씩 (길이는 몸통 키와 같게, 가로 두께는 처음 3칸의 2.5배) | 몸통 양옆, 위 끝을 몸통과 맞춤 |
| 다리 2개 | 9.5×16.15×6씩 (두 다리 가로 합 = 몸통 가로 19, 세로 = 몸통 키의 85%, 두께 = 몸통 두께) | 몸통 아래, 빈틈 없이 나란히 |
| 눈 2개 | 1×4×1씩 | 얼굴 앞면. 눈과 입꼬리 사이는 8칸 |
| 코 | 없음 | — |
| 입 | 3×2×1 + 입꼬리 1×2×1 두 개 | 눈 아래. 양 끝이 두 칸 올라간 웃는 입 |

- **그리는 법:**
  - CSS 3D 변환으로 상자를 쌓아 그린다. 새 라이브러리가 필요 없다.
  - 크기와 색은 `src/content/teacher-look.json`에 둔다. 아이가 바꾸고 싶으면 여기서 바꾼다.
- **색:** 노란 얼굴·팔, 파란 몸통, 연두 다리.
- **따라 하지 않는 것:** 특정 게임 캐릭터의 모습 그대로(색과 비례를 함께), 얼굴 그림, 로고, 옷, 효과음. 이 선생님은 머리가 몸통보다 길어서(20칸) 모습이 다르다. 머리를 다시 줄이면 색도 다시 정한다.
- **동작** (모두 코드로 움직인다)

| 장면 | 선생님 동작 | 소리 |
|---|---|---|
| 말하기 | 입 가운데 막대가 소리 크기에 맞춰 2칸 ↔ 4칸으로 벌어진다. 몸이 살짝 들썩인다 | 대사·숫자 조각 음성 |
| 숫자 부르기 | 팔을 옆으로 들어 칠판을 가리킨다. 칠판에 숫자가 한 줄씩 써진다(듣고 풀기 때는 비어 있음) | 숫자 조각 음성 |
| 기다리기 | 가끔 눈을 깜빡인다(눈 블록이 납작해짐). 몸이 천천히 오르내린다 | 없음 |
| 듣기 | 머리를 한쪽으로 기울인다. 마이크 표시 | 없음 |
| 맞았을 때 | 고개를 끄덕인다 | 없음 |
| 시연 | 화면 주판 옆에서 팔로 움직일 알을 가리킨다 | 대사 음성 |
| 수업 끝 | 정리 대사를 마친 뒤 뒤로 쓰러진다(아래 "끝 소리") | 끝 소리 |

- **입 맞추기:** 소리 파일을 재생할 때 Web Audio로 소리 크기를 읽어 입 블록을 벌린다. 그래서 숫자처럼 바뀌는 말에도 입이 맞는다.
- **끝 소리**
  - 아이가 원한 것은 블록 게임에서 캐릭터가 쓰러질 때 나는 소리다.
  - 그 게임의 실제 효과음은 저작권이 있는 소리라서 그대로 넣지 않는다.
  - 대신 **아이가 직접 녹음한 소리**를 쓴다(`src/content/end-sound.m4a`, 휴대폰 녹음기, 약 2.5초). 빌드할 때 index.html 안에 들어간다. 쓰러지기 시작하는 순간에 나도록, 앱이 뜰 때 녹음 앞의 무음 길이를 재어 두고 그 뒤부터 튼다. 재생이 안 되는 브라우저에서는 Web Audio로 만든 짧은 소리를 낸다.
  - 수업이 끝날 때 한 번만 난다. 점수나 보상이 아니라 "수업 끝" 신호다.
- 화면의 주인공은 문제와 주판이다. 선생님은 화면의 4분의 1 정도만 차지한다.

### 7.6 목소리 파일 만드는 법 (개발 도구, 앱 밖에서 한다)

목소리는 앱이 실행 중에 만들지 않는다. 개발할 때 스크립트로 미리 만들어 `media/`에 넣는다. 외부 서비스 열쇠는 git에 넣지 않는 파일에 둔다. 지하철 게임의 `.data-go-kr-key`와 같은 방식이다.

1. **대사 목록 정하기**
   - `src/content/teacher.json`에 `id`와 글자를 적는다.
2. **음성 만들기** (`npm run voice`)
   - 한국어 AI 음성 서비스에서 목소리 하나를 고른다. 후보: Typecast, 네이버 클로바보이스, ElevenLabs.
   - 스크립트가 모든 대사와 숫자 조각을 음성 파일로 만든다.
   - 파일 이름은 "글자 + 목소리 설정"의 해시로 정한다. 그래서 바뀐 줄만 다시 만든다.
3. **다듬기** (`npm run media`)
   - 앞뒤 무음을 자르고 소리 크기를 맞춘다.
   - `media/manifest.json`(id → 파일, 자막, 길이)을 만든다.
4. **확인**
   - 테스트가 `teacher.json`의 모든 `id`에 음성 파일이 있는지 검사한다.
   - 사람이 듣고, 이상한 줄은 문장을 바꿔 2번부터 다시 한다.

**양:** 대사 200줄과 숫자 조각 2천 개 안팎이다. 압축한 음성이면 몇~십몇 MB로 짐작한다.

## 8. 모드 (모두 선생님이 이끈다)

### 8.1 오늘의 수업 (기본)
- 처음 화면의 큰 버튼 하나다. 선생님이 기술 지도를 보고 오늘 할 것을 정한다.

- **방식 섞기:** 한 수업 안에서 방식을 섞는다. 기본은 "보고 풀기"와 "듣고 풀기"를 반씩이다.
  - 아이가 암산을 좋아하니, 암산이 "아직"이 아닌 칸에서는 암산 문제를 섞는다.
  - 비율은 부모 화면에서 정한다.

### 8.2 골라서 연습
- 기술 지도에서 칸을 골라 그 칸만 연습한다. 진행 방식은 8.1과 같다.

### 8.3 처음 자리 찾기
- 처음 쓸 때와 부모가 원할 때 한다. 선생님이 "어디까지 배웠는지 같이 알아봐요"로 시작한다.
- 기법 순서와 크기 순서를 따라 칸마다 2문제씩 낸다. 둘 다 맞으면 몇 칸 건너뛰고, 틀리면 되돌아온다(이분 찾기).
- 15문제 안팎이다. 아이가 언제든 그만둘 수 있고, 그때까지 결과로 지도를 채운다.
- 결과는 "됨"으로 바로 넣지 않는다. 최대 "거의"로 넣고, 연습하며 확인한다.

### 8.4 배우기
- 기법마다 선생님 설명 → 화면 주판 시연 → 아이가 실물 주판으로 따라 놓기 → 답 넣기로 확인한다.
- 시연은 4.2절의 단계 목록을 한 단계씩 보여준다. 아이가 "다음"이나 "다시 말해 주세요"를 누를 때만 움직인다.

### 8.5 플래시 암산
- 숫자가 한 줄씩 나타났다 사라진다. 선생님이 시작과 끝을 말한다.
- 빠르기는 아이가 목록에서 고른다(예: 2초, 1.5초, 1초). 앱이 저절로 바꾸지 않는다.
- 다 나온 뒤에는 시간 제한 없이 답을 넣는다.

### 8.6 주판 놀이
- 화면 주판을 마음대로 놓는다. 위에 지금 숫자를 크게 보여준다.
- 선생님이 "칠백오십을 놓아 볼래요?"처럼 말하면 실물이나 화면 주판에 놓아 본다.

### 8.7 기록
- 기술 지도(6.5절), 지난 수업 목록, 수업 다시 풀기.

## 11. 기술 구조

지하철 게임(`C:\Subway game`)과 같은 틀을 쓴다.

- **배포물**
  - 코드는 `dist/index.html` 한 파일이다.
  - 선생님 음성은 `dist/media/`에 따로 둔다. 한 파일에 넣기에는 크기 때문이다.
  - 홈 화면에 깔기 위한 `manifest.webmanifest`(이름 JUSAN), `sw.js`, 아이콘이 함께 나온다.
- **오프라인:** 서비스 워커가 처음 깔 때 `media/`까지 모두 받아 둔다. 다 받기 전에는 "선생님 준비 중"과 받은 정도를 보여준다.
- **개발:** Vite + `vite-plugin-singlefile`이다. 외부 라이브러리는 쓰지 않는 것을 기본으로 한다. 칠판과 주판은 SVG로 그린다.
- **제작 스크립트:** `scripts/`에 음성, 다듬기 스크립트를 둔다(7.6절). 앱은 외부 서비스를 부르지 않는다.
- **폴더**
```
/CLAUDE.md
/docs/SPEC.md
/docs/research-curriculum.md   급수·교육 순서 조사(출처 포함)
/src/core/      순수 함수: abacus, technique, generator, mastery, select, diagnose, teacher, numread, rng
/src/ui/        화면, 큐브 선생님(teacher-view.js), 장면 재생(음성·입 맞추기), 듣기(listen.js), 대신 쓰는 기기 음성(speech.js)
/src/content/   techniques.json, sizes.json, mastery.json, fallback.json, teacher.json, teacher-look.json, words.json
/media/         대사·숫자 조각 음성, 끝 소리, manifest.json (스크립트가 만든다)
/assets/        원본 사진(아이 사진, 선생님 후보 사진). 배포물에 넣지 않는다
/scripts/       음성 만들기, 다듬기, 아이콘 만들기
/public/        manifest, sw.js, 아이콘
/tests/
```
- **저장:** `localStorage`(try/catch 필수)에 기록, 기술 지도, 부모 설정, 선생님 모습을 둔다. 기술 지도는 기록에서 다시 계산할 수 있어야 한다. 그래서 기록이 원본이다.
- **수업 진행:** 상태 기계(대기 → 말하기 → 아이 기다리기 → 답 확인 …)로 만든다. 말하기가 끝나는 것은 음성 합성의 끝 알림으로 안다. 목소리가 없으면 글자 길이로 정한 시간이 지나면 끝난 것으로 본다.
- **테스트**(`npm test`)
  - 숫자↔주판 변환을 0~999,999,999 표본에서 되돌려 확인한다.
  - 기법 판별: 4.2절 표의 예가 모두 맞게 나와야 한다. 한 자리 덧셈·뺄셈 100가지 조합 전체를 손으로 만든 표와 비교한다.
  - 문제 만들기: 허용하지 않은 기법이 없고 목표 기법이 있어야 한다. 같은 시드는 같은 문제를 내야 한다.
  - 기술 지도: 같은 기록은 같은 지도를 만들어야 한다.
  - 오답 진단: 6.3절 표의 경우마다 맞게 짐작해야 한다.
  - 선생님 대사: 같은 상태는 같은 대사를 내야 한다. 모든 대사가 2.3절 문구 규칙(문장 길이, 금지 낱말)을 지켜야 한다.
  - 숫자 읽기: 0, 10, 101, 1000, 10000, 120,305 같은 경계 숫자를 맞게 읽어야 한다.
  - 숫자 알아듣기: 한자어 수, 아라비아 숫자, 띄어쓰기 섞인 것, 고유어 수("스물다섯")를 맞게 바꿔야 한다.
  - 금지 기능 검사, `src/core` 순수성 검사(지하철 게임 테스트를 가져온다).

## 13. 아이와 함께 쓰는 법 (부모용)

- **첫날:** 선생님 인사 듣기, 말해 보기, 처음 자리 찾기만 한다.
- **그다음:** 하루 한 수업을 한다. 학원 숙제 전 몸풀기로 쓴다.
- **일주일에 한 번:** 기술 지도를 함께 보고 학원 진도와 맞는지 이야기한다.
- **선생님 말이 이상하면** 아이가 고칠 말을 정하고, 부모가 `teacher.json`에 옮긴다. 아이가 자기 선생님을 만들어 가는 과정이다.
- **"이 문제 이상해요"라고 하면** 수업 번호를 적어 둔다. 같은 문제가 다시 나오니 함께 고칠 수 있다.
